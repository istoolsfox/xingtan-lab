# 安全测试报告

> 版本：v1.0 ｜ 日期：2026-08-30 ｜ 测试对象：杏坛学科实验平台 engine（本机 http://localhost:6174）
> 性质：**对自有服务的授权攻击测试**（defensive），目的：提交前验证攻击面，发现问题即修复。
> 方法：黑盒攻击（真实 HTTP 请求）+ 白盒代码审计 + node:test 负路径用例固化（`engine/test/api.test.js`）。

## 一、测试结论

**v0.6 加固后：全部 24 项攻击用例通过，未发现可利用漏洞。** 服务在全部攻击后保持存活。

## 二、攻击用例与结果

### 1. 路径穿越（6 变体）
`/../etc/passwd`、`%2e%2e` 双重编码、`..%5c` 反斜杠编码、`....//` 过滤绕过等 → 全部 400/403/404，响应无系统文件内容。
**防护**：`path.normalize` + `startsWith(PUB)` 前缀校验。

### 2. 认证滥用（4 项）
无 token / 伪造 48 位 token / 假 token 调删除接口 / GET 方法打到删除接口 → 全部 401 或 404。
**防护**：所有场景接口强制 Bearer 校验；token 为 24 字节 CSPRNG。

### 3. 注册接口滥用（5 项）
- 用户名 `__proto__` / `constructor` → 400（**发现项已修复**：原实现可写入 accounts.json 造成键冲突，现 `Object.create(null)` 存储 + 保留字黑名单双保险）
- 用户名 `<script>alert(1)</script>` → 400（字符白名单本就不允许 `<>`）
- 用户名 `../admin` → 400
- 超长密码（5000 字符）→ 400（长度上限 64）

### 4. 登录爆破（1 项）
同一 IP+用户名连续错 5 次 → 第 6 次返回 **429**，即使密码正确也被锁定 10 分钟（**v0.6 新增**滑动窗口限速），审计日志记录 `login-locked`。

### 5. 存储型注入（2 项）
- 场景 `title` 存入 `<img src=x onerror=alert(1)>`：原样存储（预期），前端 `mineCard` 渲染经 `esc()` HTML 转义 → **无 XSS 执行**。用户名、表达式列表、meta 同样全量转义。
- 场景对象带 `__proto__` 键：JSON 存储往返无害，服务端与前端均不合并对象属性 → **无原型污染**。
- 表达式注入：`applyScene → addExpr → parseExpr` 字符白名单 + 编译前校验，非法字符直接报错。

### 6. 拒绝服务（3 项）
- >2MB 请求体：服务端 `req.destroy()` 断开 → 客户端连接错误，服务存活
- 坏 JSON：400，服务存活
- 全部攻击后 `/api/health` 200

### 7. 纵深防御审计（白盒）
- `scenesFile(user)` 二次校验用户名字符集，即使历史数据被篡改也拼不出穿越路径
- 密码 salt+SHA-256（每账号独立 salt）；token 存储文件 `data/`、日志 `logs/` 均已 gitignore
- 未使用 eval 处理用户输入；`new Function` 仅在表达式白名单校验通过后编译，作用域无全局泄漏面（浏览器本地单机部署，风险可接受）

## 三、遗留风险声明

| 风险 | 等级 | 说明 |
| --- | --- | --- |
| HTTP 明文传输 | 低 | 设计用途为本机/课堂内网；公网部署需前置 HTTPS 反代 |
| 无 CSRF token | 低 | 状态变更接口要求 Bearer 头（非 Cookie），浏览器跨站默认无法携带自定义头 |
| 单进程内存限速 | 低 | 重启后限速窗口清零；教学场景可接受 |
| 日志记录用户名与 IP | 信息 | 仅本地文件，`logs/` 不入库 |

## 四、测试固化

攻击用例已沉淀为可重复执行的测试：`node --test engine/test/`（19 项断言，含全部负路径）。下次改动后运行即可回归。

**修复清单（本次发现并已修复）**：
1. 用户名保留字（`__proto__`/`constructor`/纯下划线）可写入账号存储 → 拒绝注册 + 无原型对象存储
2. 登录无速率限制 → IP+用户名滑动窗口限速
3. 数据文件非原子写入（崩溃可损坏）→ 临时文件 + rename
