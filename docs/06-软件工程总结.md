## 一、系统概览

**一句话**：面向中小学教师的浏览器端多学科可视化演示引擎，零构建、零 npm 依赖、按教师账号隔离保存场景。

### 1.1 分层架构

```
┌────────────────────────────────────────────────────────┐
│ 表现层  public/*.js（浏览器）                            │
│   shell.js     应用外壳：登录/导航/工作台/保存恢复（门面）   │
│   mathlab.js   数学实验室：解析→路由→绘图→互动演示          │
│   chemistry.js 化学引擎：关键帧补间 + 宏观/微观双视图        │
│   physics.js   物理仿真：matter.js + 单位换算 + HUD        │
│   surface3d.js 自研 3D 曲面渲染器（画家算法/光照/色图）      │
├────────────────────────────────────────────────────────┤
│ 服务层  server.js（Node 原生 http，单文件 ~230 行）        │
│   静态文件 + 认证(注册/登录/会话) + 场景 CRUD（按账号隔离）   │
├────────────────────────────────────────────────────────┤
│ 横切层  logger.js（日志/审计）                            │
├────────────────────────────────────────────────────────┤
│ 数据层  data/*.json（gitignore，运行时生成）               │
└────────────────────────────────────────────────────────┘
```

**分层规则**：
- 表现层模块之间**不互相 import**，只通过全局单例（`MathLab` / `ChemEngine` …）和 shell 接线通信；
- 服务层不理解任何学科语义——`scene` 对它只是带 `kind` 字段的 JSON；
- 学科语义全部留在前端模块里，服务端永远不需要因为加学科而改动。

### 1.2 核心数据流（以数学为例）

```
用户输入表达式
  → routeExpr()           路由：函数 / 极坐标 / 隐函数 / 三维
  → parseExpr()           编译：白名单校验 → JS 化 → new Function → 试算验证
  → addFn/addPolar/addImplicit   工厂：创建 entry（含绘图对象与求值闭包）
  → JSXGraph / 自研 marching squares   渲染
  → state() → POST /api/scenes     保存（服务端只存 JSON）
  → applyScene(state)     恢复（重新走同一条路由，天然向后兼容）
```

**关键设计**：保存与恢复共用同一条「表达式字符串 → 添加」链路。历史场景永不失效，因为解析路由是唯一入口。

## 二、模块职责与边界

| 模块 | 职责 | 明确不做的事 |
| --- | --- | --- |
| `server.js` | HTTP、认证、场景 CRUD、静态文件 | 不理解学科内容；不做模板渲染 |
| `logger.js` | 日志落盘/审计/轮转 | 不做日志查询 UI；绝不抛错影响业务 |
| `shell.js` | 登录态、页面路由、保存/恢复、跨模块接线 | 不实现任何学科逻辑 |
| `mathlab.js` | 表达式解析/编译、函数/极坐标/隐函数/向量场、13 个演示 | 不做账号和存储（调 shell 的 API） |
| `chemistry.js` | 反应关键帧补间、宏观/微观渲染 | 宏观场景渲染器按 `macro` 字段分派，引擎不含具体反应知识 |
| `surface3d.js` | 3D 曲面渲染 | 不做交互路由（由 mathlab 决定何时切 3D） |

**边界守则**：发现两个模块开始互相知道对方的内部结构时，先抽一个数据契约（JSON 字段）或回调接口，而不是直接引用。

## 三、设计模式应用清单（映射到真实代码）

本项目**零 class、组合优于继承**，模式以 JS 惯用法落地：

| 模式 | 落地位置 | 说明 |
| --- | --- | --- |
| **模块模式 / 单例** | 所有前端模块（`const MathLab = (() => { ... })()`） | IIFE + 闭包封装私有状态（`fns`、`board`、`mode`），只暴露 `init/state/applyScene` 等最小 API |
| **数据驱动（声明式配置）** | `CATS` 数学分类预设、`REACTIONS` 化学反应、`ATOMS/MOLS` 分子库、物理模板表、`GGB_TYPES` | **最重要的模式**：内容即数据，加内容不改代码。新增反应 = 往数组加一个对象 |
| **策略 + 工厂** | `routeExpr()` 表达式路由 → `addFn/addPolar/addImplicit/add3D`；`drawMacro()` 按 `reaction.macro` 分派渲染器；`openDemo()` 的 build 映射表 | 输入类型决定策略；`{...}[id]` 查表分派而非 if-else 链 |
| **观察者 / 事件** | `board.on('update', …)` 视图变化重算等值线；rAF 合帧防抖；`ChemEngine.init(opts)` 注入 `onCaption/onPlayState` 回调 | 事件回调里必须带「重建中」标志位防重入循环（见 `impBuilding`、`at` 标志） |
| **模板方法（钩子变体）** | 化学反应 = 固定补间算法（引擎） + 各阶段 `stages[i]()` 钩子（内容） | 引擎控制时序/插值/宏观微观同步，反应只提供关键帧数据 |
| **依赖注入** | `ChemEngine.init({macro, micro, onCaption, onPlayState})`；`Surface3D(container)` | 引擎不查询 DOM 全局，全部由调用方注入，可测试 |
| **代理 / 桩** | `parseExpr` 试算用 `new Proxy({}, {get: () => () => 1})` 当嵌套函数替身；离线测试用 JXG/DOM 桩 | 无缝验证嵌套表达式合法性与引擎逻辑 |
| **外观（Facade）** | `shell.js` 包掉 token 管理、fetch 头、页面切换、保存弹窗 | 学科模块调 `MathLab.state()` 即可被保存，不知晓 HTTP 细节 |
| **工厂函数 + 组合** | `baseEntry/finishEntry`、化学 `place(molId, x, y, rot, base)` | 对象字面量组合，避免深层继承树 |
| **数值算法模块化** | `buildImplicitCurve`（marching squares + 折线拼接 `joinSegments`） | 纯函数式管线：网格采样 → 等值线段 → 拼接 → 曲线对象 |

## 四、SOLID 原则落地分析

**S — 单一职责**
`logger.js` 只写日志（连清理都独立成启动函数）；`server.js` 只做 HTTP 与存储；解析（`parseExpr`）、路由（`routeExpr`）、绘制（`buildImplicitCurve`）、面板（`renderInspector`）各是独立函数。违反信号：一个函数同时改 DOM 和算数据——必须拆。

**O — 开闭原则（本项目最重要原则）**
对扩展开放、对修改封闭的**四个实战扩展点**：
1. 化学加反应：往 `REACTIONS` 加 JSON 式定义，引擎零改动（v0.6 的 3 个新反应即证）；
2. 数学加分类/预设：往 `CATS` 加条目，导航、工作台、演示列表自动生成；
3. 数学加表达式类型：`routeExpr` 加一个分支 + 一个 `addXxx` 工厂，既有类型不受影响（v0.6 隐函数/极坐标即证）；
4. 宏观实验场景：加一个 `drawXxx` 渲染器并在 `drawMacro` 注册一行，反应定义里引用即可。

**L — 里氏替换**
场景条目（函数/极坐标/隐函数 entry）实现同一契约：`{id,name,type,expr,params,pr,refs,color,visible,curve(s)}`。任何 entry 可被列表渲染、选中面板、删除、保存恢复无差别处理（`removeEntryObjects` 用 `o.curves || [o.curve]` 兼容差异）。

**I — 接口隔离**
每个模块对外只暴露小接口：`MathLab` 只出 `{init, setCategory, addExpr, state, applyScene, CATS}`；`ChemEngine` 只出 11 个方法。前端没有"上帝对象"。

**D — 依赖倒置**
- 服务端不依赖任何学科模块，只依赖 `scene.kind` 这一抽象契约；
- `ChemEngine` 依赖注入的回调抽象而非具体 UI；
- 前端存储依赖 `fetch('/api/scenes')` 的 JSON 契约，服务端换存储实现（未来 SQLite）不影响前端。

## 五、工程实践

### 5.1 零依赖策略
服务端只用 Node 内置模块（http/fs/path/crypto），前端只引 CDN 的 JSXGraph/matter.js/GeoGebra。**约束**：为保持"clone 即跑、双击 start.bat 可用"的教学场景价值，引入新运行时依赖前必须论证没有零依赖替代；纯算法（marching squares、DFT、RK4）一律自研。

### 5.2 安全
- 密码 salt+SHA-256，token 7 天 TTL，会话存内存（**已知债**：重启失效，见 6.x）；
- 静态文件路径规范化 + 前缀校验防目录穿越；
- 请求体 2MB 上限；表达式解析走字符白名单 + `new Function` 前置校验；
- 账号数据按文件隔离（`data/scenes/<user>.json`），接口层强制登录校验。

### 5.3 日志系统（v0.6 新增）
- `logger.js`：级别（debug/info/warn/error，`XT_LOG_LEVEL` 可调）、按天分文件 `logs/app-YYYY-MM-DD.log`、保留 30 天自动清理、控制台文件同写、任何写日志失败静默降级（**日志永远不能弄挂业务**）；
- 三类日志：`[req]` 接口请求（方法/路径/状态码/耗时）、`[audit:*]` 业务审计（注册/登录/登出/场景保存删除，含用户名）、`[boot]/[api]/[server]` 系统事件；
- 静态资源日志为 debug 级（默认不输出），避免噪音。

### 5.4 错误处理约定
- 前端：面向用户的错误用 `throw new Error('中文消息')`，由输入框下的错误区展示；引擎内部错误静默降级（求值失败返回 NaN 而非中断）；
- 服务端：API 层校验失败 → 400 + 中文 error；未知异常 → 兜底 try/catch → 500 + 日志堆栈；`res.on('finish')` 统一记请求日志。

### 5.5 兼容性纪律
`state()/applyScene()` 是场景持久化唯一通道。**任何新能力都必须让旧场景 JSON 仍可恢复**——新类型通过 `routeExpr` 路由进同一链路实现；改字段前先想清楚旧数据怎么办。

## 六、扩展指南（Cookbook）

**加一个化学反应**（约 100 行，零引擎改动）：
1. 需要新元素 → `ATOMS` 加颜色/半径；需要新分子 → `MOLS` 加几何与键；
2. `REACTIONS` 追加定义：`stages` 每个阶段函数返回 `{atoms, bonds, macro}`，**硬性约束：各阶段原子数量与索引顺序必须一致**（引擎按下标配对补间）；
3. 宏观现象：若现有场景类型不够，写 `drawXxx(ctx, st, time)` 并在 `drawMacro` 注册；
4. 校验：跑「阶段签名一致性」脚本（见 5.x 测试），再浏览器走一遍四阶段播放。

**加一个数学分类/预设**：`CATS` 加条目（presets/demos），`index.html` 侧边栏加一个 `data-cat` 按钮。

**加一个表达式类型**：`routeExpr` 加识别分支 → 写 `addXxx` 工厂（用 `baseEntry/finishEntry`）→ `addExpr` 与 `reparseEntry` 各加一行分派 → `TYPE_NAME`、列表/面板文案适配。

**加一个互动演示**：`Demos` 加 `(div, bar) => destroy` 函数，`openDemo` 的 build 映射表注册，`CATS` 对应分类的 `demos` 加条目。

**加一个学科模块**（如语文）：`index.html` 加 page 区块与导航项 → 新建 `xxx.js` 模块单例（IIFE，暴露 `init/state/applyScene`）→ `shell.js` 接线（`inited` 标志 + 保存/恢复分支）。服务端**不用改**。

**查看运行日志**：`engine/logs/app-当天.log`；调级别：`XT_LOG_LEVEL=debug node server.js`。

## 七、质量保障

**三层测试策略**（当前以人工+脚本为主，无 CI）：
1. **语法与加载**：改完必跑 `node --check`；
2. **离线冒烟**：Node + DOM/JXG 桩驱动引擎（如 mathlab 的 16 项断言、化学的阶段签名一致性校验），不依赖浏览器；
3. **浏览器验收**：登录 → 各模块走查 → 保存/清空/恢复链路 → 截图核对渲染。改动数学/化学必走第 3 层。

**一致性校验思想**：把领域约束写成可执行断言（如化学「各阶段原子序列一致」、数学「隐函数等值线半径误差 <1e-6」），而不是靠肉眼。

## 八、已知技术债与治理路线

| 债 | 影响 | 治理方向 | 状态 |
| --- | --- | --- | --- |
| JSON 文件存储，无并发锁 | 多端同账号同时保存可能互相覆盖 | 低频教学场景可接受；用户量上来换 SQLite | 未处理 |
| 无自动化测试框架/CI | 回归靠人工 | node:test 冒烟已落地（engine/test/），待接 CI | **部分完成（v0.6）** |
| 服务单进程、无 HTTPS | 仅限本机/内网课堂使用 | 部署态再引入反代 | 未处理 |
| 会话存内存，服务重启全员掉线 | 体验 | — | **已修复（v0.6）：sessions.json 持久化，过期项启动时剔除** |
| 旧反应阶段间元素索引顺序不一致 | 补间时原子颜色互变 | — | **已修复（v0.6）：电解水 stage2/3 重排，5 反应签名校验全过并固化进测试** |
| 数据文件非原子写入 | 崩溃可能损坏 accounts/scenes | — | **已修复（v0.6）：临时文件 + rename（safeWrite）** |
| 登录无速率限制 | 可被爆破 | — | **已修复（v0.6）：IP+用户名滑动窗口限速（5 次/10 分钟）** |

## 九、决策记录（ADR）

**ADR-1（2026-08-30）会话持久化到 JSON 而非引入 Redis/SQLite**
服务重启后 token 仍有效是课堂场景刚需（教师mid-class刷新不该掉线）。数据量（活跃教师数）远未到需要数据库的量级，选择 `data/sessions.json` + 启动时剔除过期项，保持零依赖。触发重评条件：活跃账号 > 数百或需要多实例部署。

**ADR-2（2026-08-30）登录限速放服务端内存而非中间件库**
滑动窗口 Map 实现 30 行内搞定，无新依赖；重启清零的代价在安全测试报告（docs/07）中评估为低风险。若未来公网部署，改挂反代层限流。

**ADR-3（2026-08-30）测试选型 node:test 而非 jest/vitest**
零依赖纪律的延伸：Node 18+ 内置测试运行器满足冒烟+API 集成需求（子进程起真实服务测负路径），无安装成本。测试分两层：`engine.test.js`（引擎离线逻辑，浏览器环境桩）+ `api.test.js`（HTTP 集成与安全用例，XT_DATA_DIR 隔离测试数据）。
